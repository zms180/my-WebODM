## 部署架构

GeoModel 系统由以下组件组成：

```
┌─────────────────────────────────────────────────┐
│              GeoModel 系统架构                   │
├─────────────────────────────────────────────────┤
│                                                 │
│  ┌─────────────┐         ┌──────────────┐      │
│  │   webapp    │────────▶│   broker     │      │
│  │  (Django)   │         │   (Redis)    │      │
│  └─────────────┘         └──────────────┘      │
│         │                                       │
│         ▼                                       │
│  ┌─────────────┐         ┌──────────────┐      │
│  │   worker    │────────▶│      db      │      │
│  │  (Celery)   │         │ (PostgreSQL) │      │
│  └─────────────┘         └──────────────┘      │
│         │                                       │
│         ▼                                       │
│  ┌─────────────┐                               │
│  │ node-odx-1  │                               │
│  │  (NodeODX)  │                               │
│  └─────────────┘                               │
│                                                 │
└─────────────────────────────────────────────────┘
```

**镜像列表**：

- `geomodel_webapp:v1.0` - Web 应用和 Worker（基于 webodm/webodm_webapp）
- `geomodel_db:v1.0` - 数据库（基于 webodm/webodm_db）
- `geomodel_nodeodx:v1.0` - 处理节点（基于 webodm/nodeodx:gpu）
- `redis:7.0.10` - 消息代理（官方镜像）

## 构建镜像

### 1. 构建 webapp 镜像

```bash
# 在项目根目录执行
docker build \
  --platform linux/amd64 \
  --pull=false \
  -t geomodel_webapp:v1.0 \
  -f deploy-package/Dockerfile.webapp \
  .

# 构建说明：
# --platform linux/amd64  确保构建 amd64 架构镜像
# --pull=false            不重新拉取基础镜像，使用本地现有镜像
# -t geomodel_webapp:v1.0 镜像名称和标签
# -f deploy-package/Dockerfile.webapp  指定 Dockerfile 文件
```

### 2. 构建 nodeodx 镜像

```bash
docker build \
  --platform linux/amd64 \
  --pull=false \
  -t geomodel_nodeodx:v1.0 \
  -f deploy-package/Dockerfile.nodeodx \
  .
```

### 3. 重命名 db 镜像

```bash
# 不需要构建，直接重命名现有镜像
docker tag webodm/webodm_db:latest geomodel_db:v1.0
```

### 4. 验证镜像

```bash
docker images | grep geomodel

# 应该看到：
# geomodel_webapp    v1.0    xxx123    Just now    2.5GB
# geomodel_nodeodx   v1.0    yyy456    Just now    4.0GB
# geomodel_db        v1.0    zzz789    Just now    300MB
# redis              7.0.10  aaa111    1 week ago  117MB
```

## 导出镜像

### 1. 导出所有镜像为单个文件

```bash
docker save \
  geomodel_webapp:v1.0 \
  geomodel_db:v1.0 \
  geomodel_nodeodx:v1.0 \
  redis:7.0.10 \
  -o geomodel-images.tar

# 查看文件大小
ls -lh geomodel-images.tar
# 预计大小：约 7 GB
```

### 2. 准备配置文件包

创建部署配置目录：

```bash
mkdir -p geomodel-deploy
cd geomodel-deploy

# 复制配置文件
cp ../deploy-package/docker-compose.yml .
cp ../deploy-package/docker-compose.nodeodx.yml .
cp ../deploy-package/.env.example .env
cp ../deploy-package/geomodel.sh .
cp ../deploy-package/私有部署指南.md .

# 编辑 .env 配置（可选，也可以在客户服务器上修改）
nano .env

cd ..
```

### 3. 打包配置文件

```bash
tar -czf geomodel-deploy.tar.gz geomodel-deploy/

# 查看文件大小
ls -lh geomodel-deploy.tar.gz
# 预计大小：约 20 KB（仅配置文件）
```

### 4. 传输文件清单

需要传输到客户服务器的文件：

```
✓ geomodel-images.tar      (约 7 GB)  - Docker 镜像文件
✓ geomodel-deploy.tar.gz   (约 20 KB) - 配置和脚本
```

**传输建议**：

- U 盘拷贝（推荐）：适合离线环境
- SCP 传输：`scp geomodel-*.* user@server-ip:/opt/`
- 内网共享：通过 SMB/NFS 共享

## 客户服务器部署

### 1. 准备环境

```bash
# SSH 登录客户服务器
ssh user@customer-server-ip

# 创建部署目录
sudo mkdir -p /opt/geomodel
cd /opt/geomodel

# 将文件复制到此目录
# geomodel-images.tar
# geomodel-deploy.tar.gz
```

### 2. 导入镜像

```bash
# 导入 Docker 镜像（需要几分钟）
docker load -i geomodel-images.tar

# 验证导入成功
docker images | grep -E "(geomodel|redis)"

# 应该看到：
# geomodel_webapp    v1.0    xxx123    ...    2.5GB
# geomodel_nodeodx   v1.0    yyy456    ...    4.0GB
# geomodel_db        v1.0    zzz789    ...    300MB
# redis              7.0.10  aaa111    ...    117MB
```

### 3. 部署配置

```bash
# 解压配置文件
tar -xzf geomodel-deploy.tar.gz
cd geomodel-deploy/

# 编辑配置文件
nano .env
```

**关键配置项**：

```bash
# 服务器 IP 地址（改为实际服务器 IP）
WO_HOST=192.168.1.100

# 服务端口
WO_PORT=8000

# 数据存储目录
WO_MEDIA_DIR=appmedia  # 存储用户上传的图片和结果
WO_DB_DIR=dbdata       # 数据库文件

# 安全密钥（必须修改为随机字符串）
WO_SECRET_KEY=your_random_secret_key_here_min_50_chars_long

# 并发数（根据服务器 CPU 核心数调整）
WEB_CONCURRENCY=4

# 默认处理节点数量
WO_DEFAULT_NODES=1
```

### 4. 启动服务

```bash
# 启动 GeoModel
chmod +x geomodel.sh
./geomodel.sh

# 或手动启动
docker-compose -f docker-compose.yml -f docker-compose.nodeodx.yml up -d

# 查看服务状态
docker-compose ps

# 应该看到所有服务都是 Up 状态：
# NAME        STATE    PORTS
# webapp      Up       0.0.0.0:8000->8000/tcp
# worker      Up
# db          Up       5432/tcp
# broker      Up       6379/tcp
# node-odx-1  Up       3000/tcp
```

### 5. 验证部署

```bash
# 查看 webapp 日志
docker-compose logs webapp

# 等待看到类似输出：
# webapp | [INFO] Starting gunicorn
# webapp | [INFO] Listening at: http://0.0.0.0:8000

# 测试访问
curl http://localhost:8000

# 从其他机器访问
# http://192.168.1.100:8000
```

### 6. 创建管理员账户

```bash
# 进入 webapp 容器
docker exec -it webapp bash

# 创建管理员用户
python manage.py createsuperuser

# 按提示输入：
# Username: admin
# Email: admin@example.com
# Password: ********

# 退出容器
exit
```

## 配置说明

### docker-compose.yml 说明

```yaml
version: "2.1"
volumes:
  dbdata: # 数据库持久化卷
  appmedia: # 媒体文件持久化卷
services:
  db:
    image: geomodel_db:v1.0
    volumes:
      - ${WO_DB_DIR}:/var/lib/postgresql/data:Z

  webapp:
    image: geomodel_webapp:v1.0
    ports:
      - "${WO_PORT}:8000/tcp"
    volumes:
      - ${WO_MEDIA_DIR}:/webodm/app/media:z # 仅挂载数据目录
    depends_on:
      - db
      - broker
      - worker

  broker:
    image: redis:7.0.10

  worker:
    image: geomodel_webapp:v1.0
    volumes:
      - ${WO_MEDIA_DIR}:/webodm/app/media:z # 仅挂载数据目录
```

**关键点**：

- ✅ **不挂载源码**：所有自定义代码已打包在镜像内部
- ✅ **仅挂载数据**：只挂载 `WO_MEDIA_DIR`（用户数据）和 `WO_DB_DIR`（数据库）
- ✅ **网络配置**：使用 `host-gateway` 而非硬编码 IP

### docker-compose.nodeodx.yml 说明

```yaml
version: "2.1"
services:
  node-odx-1:
    image: geomodel_nodeodx:v1.0 # 自定义代码已在镜像内部
    deploy:
      resources:
        reservations:
          devices:
            - driver: cdi
              device_ids:
                - nvidia.com/gpu=all
              capabilities: [gpu]
```

**关键点**：

- ✅ **GPU 支持**：使用 CDI 驱动挂载 NVIDIA GPU
- ✅ **无源码挂载**：ODX 自定义代码已打包在镜像内

### 环境变量说明

| 变量               | 说明           | 默认值        | 是否必改    |
| ------------------ | -------------- | ------------- | ----------- |
| `WO_HOST`          | 服务器 IP 地址 | `0.0.0.0`     | ✅ 必须改   |
| `WO_PORT`          | 服务端口       | `8000`        | 建议保持    |
| `WO_SECRET_KEY`    | Django 密钥    | `changeme...` | ✅ 必须改   |
| `WO_MEDIA_DIR`     | 媒体文件目录   | `appmedia`    | 按需修改    |
| `WO_DB_DIR`        | 数据库目录     | `dbdata`      | 按需修改    |
| `WEB_CONCURRENCY`  | 并发进程数     | `2`           | 按 CPU 调整 |
| `WO_DEBUG`         | 调试模式       | `NO`          | 保持 NO     |
| `WO_DEFAULT_NODES` | 默认节点数     | `1`           | 按需调整    |

## 常见问题

### 1. 如何迁移现有 WebODM 数据？

如果服务器已运行 WebODM，需要迁移数据：

```bash
# 1. 停止旧的 WebODM
cd /old/webodm/path
docker-compose down

# 2. 备份数据
docker run --rm \
  -v webodm_db:/source \
  -v $(pwd):/backup \
  alpine tar czf /backup/db_backup.tar.gz -C /source .

docker run --rm \
  -v webodm_media:/source \
  -v $(pwd):/backup \
  alpine tar czf /backup/media_backup.tar.gz -C /source .

# 3. 在新 GeoModel 中恢复数据
cd /opt/geomodel/geomodel-deploy

# 创建新卷
docker volume create geomodel_dbdata
docker volume create geomodel_appmedia

# 恢复数据
docker run --rm \
  -v geomodel_dbdata:/target \
  -v $(pwd):/backup \
  alpine tar xzf /backup/db_backup.tar.gz -C /target

docker run --rm \
  -v geomodel_appmedia:/target \
  -v $(pwd):/backup \
  alpine tar xzf /backup/media_backup.tar.gz -C /target

# 4. 修改 .env 使用新卷
# WO_DB_DIR=geomodel_dbdata
# WO_MEDIA_DIR=geomodel_appmedia
```

### 2. GPU 不可用怎么办？

如果服务器没有 GPU 或 GPU 不可用：

```bash
# 使用 CPU 版本启动
docker-compose -f docker-compose.yml up -d

# 不启动 docker-compose.nodeodx.yml 即可
```

### 3. 如何修改端口？

```bash
# 编辑 .env
nano .env

# 修改端口
WO_PORT=9000

# 重启服务
docker-compose down
docker-compose -f docker-compose.yml -f docker-compose.nodeodx.yml up -d
```

### 4. 如何查看日志？

```bash
# 查看所有服务日志
docker-compose logs -f

# 查看特定服务日志
docker-compose logs -f webapp
docker-compose logs -f worker
docker-compose logs -f node-odx-1

# 查看最近 100 行
docker-compose logs --tail=100 webapp
```

### 5. 服务启动失败怎么办？

```bash
# 检查端口占用
netstat -tuln | grep 8000
# 或
ss -tuln | grep 8000

# 检查磁盘空间
df -h

# 检查 Docker 状态
systemctl status docker

# 清理并重启
docker-compose down
docker system prune -f
docker-compose up -d
```

### 6. 如何更新镜像？

```bash
# 1. 在开发服务器重新构建镜像
docker build --platform linux/amd64 --pull=false -t geomodel_webapp:v1.1 -f deploy-package/Dockerfile.webapp .
docker build --platform linux/amd64 --pull=false -t geomodel_nodeodx:v1.1 -f deploy-package/Dockerfile.nodeodx .

# 2. 导出新镜像
docker save geomodel_webapp:v1.1 geomodel_nodeodx:v1.1 -o geomodel-images-v1.1.tar

# 3. 传输到客户服务器并导入
docker load -i geomodel-images-v1.1.tar

# 4. 修改 docker-compose.yml 中的镜像版本
# image: geomodel_webapp:v1.1

# 5. 重启服务
docker-compose down
docker-compose up -d
```

### 7. 如何备份和恢复？

```bash
# 定期备份
# 1. 备份数据库
docker exec db pg_dump -U postgres webodm > backup_$(date +%Y%m%d).sql

# 2. 备份媒体文件
tar -czf media_backup_$(date +%Y%m%d).tar.gz appmedia/

# 恢复
# 1. 恢复数据库
docker exec -i db psql -U postgres webodm < backup_20250828.sql

# 2. 恢复媒体文件
tar -xzf media_backup_20250828.tar.gz
```

### 8. 性能优化建议

```bash
# 1. 增加并发数（根据 CPU 核心数）
# .env 中设置
WEB_CONCURRENCY=8  # 推荐为 CPU 核心数

# 2. 增加处理节点
# 可以添加多个处理节点
# 复制 docker-compose.nodeodx.yml 中的 node-odx-1 服务
# 命名为 node-odx-2, node-odx-3 等

# 3. 调整数据库连接池
# 在 webapp 容器中修改 settings.py（已在镜像内部）

# 4. 启用 Redis 持久化
# docker-compose.yml 中为 broker 添加 volume
```

## 架构优势

### 传统部署 vs 镜像部署对比

| 项目           | 传统部署（源码）   | 镜像部署          |
| -------------- | ------------------ | ----------------- |
| **源码暴露**   | ✗ 完全暴露         | ✅ 完全隐藏       |
| **部署复杂度** | ✗ 高（需配置环境） | ✅ 低（一键导入） |
| **更新方式**   | ✗ 修改源码         | ✅ 替换镜像       |
| **依赖管理**   | ✗ 手动安装         | ✅ 镜像内置       |
| **环境一致性** | ✗ 可能不一致       | ✅ 完全一致       |
| **客户维护**   | ✗ 需要技术能力     | ✅ 简单命令       |

## 总结

本部署方案的核心优势：

1. ✅ **源码保护**：客户服务器只有镜像，看不到源码
2. ✅ **简化部署**：一键导入镜像，一键启动服务
3. ✅ **便于更新**：重新构建镜像即可升级
4. ✅ **环境一致**：开发和生产环境完全一致
5. ✅ **易于维护**：客户只需几个 Docker 命令

部署流程总结：

```
开发服务器                          客户服务器
──────────                          ──────────
1. 构建镜像                         4. 导入镜像
   (源码 COPY 进镜像)                   docker load
         ↓                                  ↓
2. 导出镜像                         5. 解压配置
   docker save                          tar -xzf
         ↓                                  ↓
3. 传输文件                         6. 启动服务
   (镜像 + 配置)                        ./geomodel.sh
```

**客户服务器最终状态**：

- ✅ 4 个 Docker 镜像（源码已在镜像内部）
- ✅ 1 个配置文件（.env）
- ✅ 2 个编排文件（docker-compose.yml）
- ✅ 1 个启动脚本（geomodel.sh）
- ❌ **无任何源码文件**
